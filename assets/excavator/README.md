# EX 200 挖掘机模型 v2

面向 Three.js 施工机械游戏的原创通用履带式挖掘机，不对应特定厂商尺寸。

v2 调整铲斗入口：连续薄楔形前刃（尖端厚 1.4 厘米）、薄斗齿（尖端厚 1.2 厘米）、平滑衔接的斗底。对应 GLB、Blender 源文件及 22 个碰撞代理同步更新。`rig.json` 的 `bucketGeometry` 记录共享的斗内截面、入口最低点和厚度，供游戏贴地辅助与装料判定使用。

## 文件

- `excavator.blend`：独立的 Excavator_Studio 场景，保留分件、液压缸约束、铲斗四连杆驱动、摄影棚灯光。原始默认场景保留。
- `excavator.glb`：网页用 PBR 模型，15 个网格、35 个材质图元、70,500 个三角形，约 1.33 MB。保留关节与标注节点，不含摄影棚和碰撞代理。
- `excavator-preview.png`：将导出的 GLB 重新导入 Blender 后渲染的外观预览。浏览器效果取决于灯光与色彩设置。
- `excavator.rig.json`：关节轴、相对初始姿态的角度范围、液压缸锚点、连杆参数及中文标注。
- `excavator.physics.json`：22 个独立凸包碰撞代理的顶点，坐标位于各自 parent 关节的局部空间；不应将整个铲斗合并成单个凸包。
- `validation.json`：导出统计及铲斗连杆闭合检查结果。

## 操作和接入

Blender 使用米、Z 向上、X 向前；GLB 和碰撞配置使用米、Y 向上、X 向前。坐标转换是 `(x,y,z) -> (x,z,-y)`。

在 Blender 中选择 `J_Slew` 绕 Z 旋转，选择 `J_Boom`、`J_Stick`、`J_Bucket` 绕各自局部 Y 旋转。液压缸利用 Damped Track 约束保持端点对齐，铲斗摇杆利用内置数学表达式驱动，连接杆跟随铲斗连接点。请使用较小动作检查姿态；写入的关节范围仍是初始调试值。

GLB 中的关节按 rig.json 提供的局部轴，在导入时的初始姿态上叠加旋转。Blender 约束和驱动不会随静态 GLB 成为可执行逻辑：游戏必须重建液压缸朝向、连杆几何解算及关节限位，不能只旋转动臂后期待液压缸自动跟随。

GLTFLoader 可能规范化包含空格的对象名称；接入时可按 `userData.name` / glTF 原始节点名建立映射，或对配置和模型统一执行名称规范化。关节名称 J_* 不含空格。

碰撞配置只提供几何，需由 Rapier 等物理引擎创建刚体和凸包。斗底、背板、两侧与斗齿分块，保留斗口；本项目已在 Rapier 中接入石头装载、卸料与碰撞，测试范围见项目根目录 README。

## 已验证

- GLB 成功导出并重新导入 Blender，复核导出模型的外观。
- 铲斗相对初始姿态 -48、-24、0、24、48 度下，连接杆端点闭合误差均小于 0.000001 米。
- 可编辑源场景与网页模型分别保留；关节、中文标注节点和碰撞配置独立交付。

## 当前边界

- 已进行固定条件下的地面接触与石头装载测试，但尚未验证整机自碰撞和液压缸全行程，当前关节范围不是经过工程验证的安全工作包络。
- 履带在 GLB 中已合并为底盘的静态几何，行走动画需另行实现；源文件保留逐节履带。
- 材质为基础 PBR，没有烘焙的泥土、划痕与磨损纹理。
- 四连杆为可闭合的示意机构，不是某个真实型号的精确尺寸复刻。
- 本次交付是机械模型，不包含城市工地和完整游戏。

## 重建

在 Blender 的 Python 环境中，以同一 globals 字典按顺序执行项目 `scripts/model_excavator_01.py` 至 `05.py`。脚本使用当前项目绝对输出路径，会新建场景并生成模型，不要在已有生成场景上重复运行单个阶段。第四阶段修正并验证第三阶段的连杆，必须执行完毕后再导出。预览渲染单独执行。

生成基础模型后，必须再以 `excavator.blend` 为输入运行 `scripts/refine_bucket.py`，才能生成含 `bucketGeometry` 配置的 v2 游戏资产。之后运行 `scripts/render_excavator_preview.py` 更新预览。只运行原始 01～05 阶段会恢复 v1 入口。
